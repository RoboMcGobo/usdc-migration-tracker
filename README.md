# USDC Migration Tracker

Static dashboard tracking the Cosmos ecosystem migration from Noble USDC (USDC.n) to Injective USDC (USDC.inj), chain by chain. No backend: the page fetches current balances live from public REST endpoints in the visitor's browser, and a scheduled GitHub Action commits one snapshot per day to `data/snapshots.json` so every visitor sees the same history.

## Layout

| Path | Purpose |
|---|---|
| `index.html` | The dashboard. Self-contained; reads `data/config.json` and `data/snapshots.json` from the same origin and falls back to copies embedded in the file if those are unreachable (for example when opened from disk). |
| `data/config.json` | Every Noble IBC counterparty from the chain registry plus XPLA: chain ids, REST endpoints, USDC.n and USDC.inj denoms, channel ids, escrow addresses. Regenerated by the Action. |
| `data/snapshots.json` | One entry per UTC day. Seeded with the 2026-10-05 baseline. |
| `data/retired.json` | Chains that are shut down or have deprecated IBC (currently Kujira and Sei). Their USDC.n is shown in the counterparties table but excluded from the tracked set, the action list and the recoverable total. Edit this file to add or remove one; the Action folds it into `config.json`. |
| `data/last_run_full.json` | Full output of the latest snapshot run, including per-chain errors, for debugging. |
| `scripts/build_config.py` | Rebuilds `data/config.json` from a sparse clone of `cosmos/chain-registry`. |
| `scripts/snapshot.py` | Queries the endpoints and appends today's snapshot. Refuses to write if fewer than five chains were measurable. |
| `.github/workflows/snapshot.yml` | Daily cron at 06:10 UTC plus manual trigger. |

## Setup

1. Create a repository and push these files to `main`.
2. Settings, Pages: Source "Deploy from a branch", branch `main`, folder `/ (root)`.
3. Settings, Actions, General: Workflow permissions "Read and write permissions" (the workflow also declares `contents: write`).
4. Actions tab: run "Daily USDC migration snapshot" once by hand to confirm it commits.

The page is then at `https://<org>.github.io/<repo>/`.

## What the page shows

KPIs: Noble total USDC supply (the public figure) with change over the selected window (24h, 7d, 30d, since Sept 1), runway to January 12, 2027 with the 7d and 30d migration pace against the daily pace needed, USDC.inj supply on Injective and the share exported over IBC, and the tracked chain count. Two panels break down where the Noble supply sits (live chains, Noble itself, parked on Injective, retired chains, unregistered channels) and show the live composition of Osmosis transmuter pool 3497, refreshed every five minutes. The chain table adds each chain's share of remaining USDC.n, whether USDC.inj is listed in its chain-registry assetlist, and a prefilled Skip:Go migration link.

## Measurement notes

USDC.n on each chain is the bank supply of the one-hop IBC denom from Noble; USDC.inj is the same for `erc20:0xa00C59fF5a080D2b954d0c75e46E22a0c371235a` from Injective (XPLA: two hops via the Cosmos Hub). History comes from IBC escrow accounts: Noble's escrow balance per channel equals the USDC.n outstanding through that channel, and Noble has public archive nodes that answer height-pinned queries back past September 1. Injective's public nodes keep about one week of state, so USDC.inj history beyond that comes only from the daily snapshots. The 25,000 USDC.n threshold is applied to the larger of on-chain supply and Noble escrow so that a chain with dead endpoints is not dropped.

To run locally:

```
python3 scripts/build_config.py   # optional, needs git
python3 scripts/snapshot.py
python3 -m http.server 8000        # then open http://localhost:8000/
```
